# Aspire v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn Aspire into a signed-in, Jarvis-style general assistant with a new UI, a Gmail morning briefing, send-for-me actions, learning features, and full Telegram/Discord/Slack bots that act as linked users.

**Architecture:** One Next.js 16 app on Vercel (web/). Supabase (Seoul) provides auth plus a small Postgres store used only for bot links, Slack installs and opt-in cloud sync. Bots are webhook routes on the same app that reuse the existing `ask()` brain and tools; long work runs in `after()`. Reminders for linked users fire from Supabase `pg_cron` + `pg_net` calling a secured route.

**Tech Stack:** Next.js 16.4.6 (App Router, `proxy.ts`), React 19.3, TypeScript, Tailwind v4, lucide-react, motion, 21st.dev components, `@supabase/supabase-js` + `@supabase/ssr`, Anthropic SDK (`claude-opus-5-5`), Azure Speech REST, vitest.

**Spec:** `docs/superpowers/specs/2026-11-20-aspire-v2-design.md`

## Global Constraints

- All app code lives in `web/`; tests in `web/tests/*.test.ts`; run tests with `cd web && npx vitest run`, types with `npx next typegen && npx tsc --noEmit`, lint with `npx eslint .`.
- Next 16: session/redirect logic goes in `web/proxy.ts` (the `middleware` file is deprecated); background work uses `after` from `next/server`.
- Languages: `mn zh en ru de`, auto-detected per message (existing `lib/lang.ts`); every new UI string exists in all five in `lib/ui-text.ts`.
- Nothing is sent, posted or dialed without the user tapping a confirm control in the web app; bots only reply in the chat that addressed them.
- No personal data in Supabase for users who have not linked a bot. Linking a bot = cloud sync on (the checkbox is the consent).
- Secrets only in `web/.env.local` (git-ignored) and Vercel env; never in the repo, logs, chat or error messages. Run the secret scan (`git diff --cached | grep -E "sk-ant-|AIza|AQ\.|xox[bp]-|SUPABASE_SERVICE"`) before every push.
- Supabase project `aspire`, org `rgnzljarfxohuhvgbjav`, region `ap-northeast-2`; Vercel function region `icn1`.
- UI tokens: bg `#060B16`; glass `rgba(255,255,255,.06)` + `backdrop-filter: blur(20px)`; cyan `#38DCFF` (idle/listening), violet `#8B7CFF` (thinking), amber `#FFB547` (speaking). Lucide icons only (no emoji as icons); touch targets ≥ 44 px; text contrast ≥ 4.5:1; body 16–18 px / line-height 1.5.
- Motion: only `transform`/`opacity`/`filter`; messages fade+rise ~250 ms; sheets spring with no bounce from their trigger; buttons `scale(0.97)` on press; no animation on keyboard-initiated actions; every animation has a `prefers-reduced-motion` variant (cross-fade only) and `prefers-reduced-transparency` makes panels solid.
- Every API route except bot webhooks, `/api/cron/*`, `/auth/*` and `/api/bots/slack/oauth` requires a Supabase session (401 JSON `{error:"signed_out"}` otherwise).

## Review Focus

1. **Session expires while the app is open**: API calls return 401 and the client sends the user to `/login` with a short notice, never a blank error. (Task 3 test `requireUser returns null for an expired session` + Task 7 client handling.)
2. **Gmail access revoked or refresh token expired**: the briefing still speaks weather and reminders and shows "Reconnect Gmail"; `check_email` returns a tool error the AI explains. (Task 11 test `briefing without mail when Google refresh fails`.)
3. **Telegram re-delivers the same update** (webhook retry after a slow answer): the bot answers once. (Task 13 test `duplicate update_id is ignored`.)
4. **A wrong or hostile webhook URL in Connections**: refused before any request is made (no SSRF). (Task 9 test `rejects non-allow-listed webhook urls`.)
5. **The AI fails or is slow inside Discord/Slack**: the platform is acknowledged within 3 s and a fallback line is posted instead of silence. (Task 14/15 tests `posts fallback when ask throws`.)
